# Capability HTTP 落地踩坑与经验

> **范围**：`ops-desk-api` 的 `kind=http` 能力层（阶段 H4 / W2 / W3）＋ `ops-desk-mock-oa` 桩服务联调
> **时点**：2026-09-19
> **筛选原则**：只收录**机制性**问题——即"换个人、换台机器、换个环境还会再犯"的那种。
> 纯笔误、纯本机配置不在此列（本机特有的另列第 4 节，便于区分"代码问题"与"环境问题"）。
> **分级**：★★★ 生产必然/极可能 · ★★ 生产可能（取决于环境或升级）· ★ 本机/沙箱特有

## 2. ★★★ 生产必然 / 极可能发生



### 2.1 幂等键嵌非 ASCII，HTTP 头只能承载 latin-1

**现象**：联调时第一个写请求就崩：

```
UnicodeEncodeError('latin-1', 'oa.ticket.create:u-1:超时测试:2026-09-19',
                    21, 25, 'ordinal not in range(256)')
```

**根因**：幂等键模板通常会嵌**用户输入**（我们的设计模板就是
`oa.ticket.create:{{_user_id}}:{{title}}:{{_date}}`，`title` 是"打印机故障"这类中文）。
HTTP 头按 RFC 只能承载 latin-1，`urllib` 直接抛异常。

**后果的严重性**：不是"偶尔失败"，而是**所有含非 ASCII 参数的写操作全部发不出去**——
中文业务场景下等于写能力完全不可用。

**为什么单测抓不到**：单测参数全是 `"x"` / `"keyword"` 这类 ASCII。
**覆盖了逻辑，但覆盖不到"真实输入长什么样"。**

**修法**（`http_generic.py`）：

- 幂等键 → `urllib.parse.quote(value, safe=":._-")` 规范成 **ASCII 安全且确定性**的形态
  - 必须**确定性**（同输入同键），否则去重直接失效
  - 保留 `:._-` 分隔符，便于对账
- `header_map` 的值 → **不静默改写**（有业务含义，悄悄编码对方看不懂）→ **早失败**报
`args_schema_invalid`，并提示改用 query/body 承载
- 另加一道：所有出站头做一次 latin-1 校验，把错误提前到我们自己的语义里

**可复用判据**：**凡是"拼进协议位置"的字段（头、URL、文件名、SQL），都要单独想一遍编码边界。**
把它写进测试时，参数里必须出现一个非 ASCII 样本。

### 2.2 环境代理劫持内网调用

**现象**：联调报 `HTTP Error 502: Bad Gateway`——**但服务明明是通的**（`curl` 也 200）。

**根因**：`urllib.request.urlopen` **默认读** `HTTP_PROXY` **/** `http_proxy`。
本机设了出口代理，于是所有打给 `127.0.0.1` / 内网 OA 的请求都被送到出口代理。

**后果的严重性**：任何设了 `HTTP_PROXY` 的企业环境都会踩；而且**失败形态是一个看不懂的
502，看起来像网络故障而不是配置问题**——最难查的那一类。

**修法**：构造显式 opener，**默认不走任何代理**：

```python
explicit = os.environ.get("OPS_CAPABILITY_HTTP_PROXY", "").strip()
handler = (urllib.request.ProxyHandler({"http": explicit, "https": explicit})
           if explicit else urllib.request.ProxyHandler({}))
urllib.request.build_opener(handler)
```

理由：`base_url` 是运维选定的**内网**端点，把它经环境里的出口代理转发几乎总是错的。
确实需要代理时**显式开**，不靠环境的隐式代理。

**测试写法**（值得复用）：真起一个本地 `http.server`，把 `HTTP_PROXY` 指向**必然连不上**的
地址（如 `http://127.0.0.1:1`），断言调用**仍然成功**——用"能否调通"反证，不依赖
`urllib` 内部结构。

> 我们第一版测试是去 `opener.handlers` 里找 `ProxyHandler` 断言 `proxies == {}`，
> **问错了对象**（`ProxyHandler` 不落在 `handlers` 里）→ 断言永远不过。
> **行为断言 > 结构断言。**

---



### 2.3 阻塞 IO 跑在事件循环里

**现象**：不报错，只是在并发下整体变慢/卡住。

**根因**：`FastAPI`（asyncio）里，`gateway._adispatch` 在适配器没有 `ainvoke` 时会**同步调用**
`invoke`；而 `UrllibHttpTransport` 是**阻塞**的 `urllib`。于是**一次 8 秒的下游调用会把整个
事件循环按住 8 秒**，期间所有其他请求排队。

**为什么单测抓不到**：单测串行执行，看不出并发退化；`FakeHttpTransport` 更是零耗时。

**修法**：给 `GenericHttpAdapter` 实现 `async def ainvoke`，把阻塞传输放到线程里
（`asyncio.to_thread`），异步路径优先走它。

**可复用判据**：**在 async 应用里引入任何同步 IO 客户端，都要问一句"它在哪个线程跑"。**
`urllib` / `requests` / 同步 SDK 全部适用。

---



### 2.4 写操作在超时后重试 → 建出两张单据

**现象**：网络抖动后同一个业务动作出现两条记录。

**根因**：超时**不等于失败**——请求可能已经到达并成功，只是响应没回来。此时重试就会
重复执行。

**修法**（已落地）：

- 传输层：`RETRYABLE = {"GET"}`——**写操作永不自动重试**
- 语义层：幂等键作为 `Idempotency-Key` 头**下推给下游**，由下游去重
- 记录层：防重表（见 2.11）
- 查询层：写操作的"失败"必须靠**幂等键 + 主动查询确认**，不能靠重试

**联调的实证方式**（很值得复用）：让桩服务"睡 3 秒再成功"，代理侧 `timeout_ms=2s`，
然后断言**桩服务侧该幂等键的** `attempts` **恰为 1**。
——**断言"对端被调用了几次"，比断言"我们返回了什么"更接近真问题。**

---



### 2.5 写操作闸挂错了维度

**现象**：一个 `risk_level: medium` 但**会真写**下游的能力，Policy 完全放行。

**根因**：`risk_level`（危险程度）与 `side_effect`（有无副作用）**是两个维度**，
用前者代理后者必然漏。

**修法**：

- `CapabilitySpec` 增加 `side_effect ∈ {none, read, write, irreversible}`
- Policy 增加写闸：`side_effect ∈ {write, irreversible}` 默认拒，只有 Host 侧
`_host_policy.allow_write`（单次放行）或 env 能开
- `allow_write` 必须进 `HOST_ONLY_POLICY_KEYS`——否则模型在 plan 顶层写它
（虽然会被忽略，但**没人测得到它被忽略**）
- 加载期强校验（V1/V2/V8）把"写操作必须声明幂等键与人工确认"变成**配置错误**而非运行期故障

**可复用判据**：**新增一个"正交维度"时，先问"现有的哪个字段正在代理它"。**
代理关系往往已经存在，而且已经漏了。

---



### 2.6 下游业务码不归一

**现象**：老系统返回 `HTTP 200` + `{"code": 1001}`；错误字符串各家不统一；
有的接口超时其实已成功。模型面对一堆无法决策的字符串。

**修法**：建立**七个稳定错误码**（`unknown_id` / `disabled` / `policy_blocked` /
`args_schema_invalid` / `duplicate_id` / `upstream_error` / `permission_denied`），
manifest 的 `error_map` 负责把下游业务码映射进来，**映射值必须是这七个之一**（加载期校验）。

要点：

- **下游原文一律不外泄**（联调断言了 `"参数不合法" not in error`）
- 归一化只决定"模型看到的词"，不改变"我们记的日志"——排查仍要看原文

---



### 2.7 `tenant_scoped` 只在 Policy 检查、没下推到下游

**现象**：能力标了"需要租户"，Policy 也检查了 ctx 里有租户谓词——**但那个谓词从没传给下游**。
等于：**检查了，但没用上。**

**修法**（V4）：`tenant_scoped: true` 且 `kind=http` 时，manifest **必须**声明
`tenant_param`（怎么下推：query / body / header）。把"有没有真的下推"变成**加载期可验证**的约束。

**联调怎么证**：桩服务对需要租户的接口做**硬失败**（缺 `X-Ops-Tenant` → 2003），
并在响应里**回显 tenant**；请求日志再确认"不声明 `tenant_param` 的接口确实没带这个头"。

**可复用判据**：**"检查"和"使用"是两件事。** 任何"我们校验了 X"的代码，都要再问一句
"X 有没有被真的用上"。

---



### 2.8 校验规则写在恒为空的字段上 → 死代码

**现象**：规则"仅 `kind=http` 可声明 `http` 块"写在 `spec.http` 上判——而 `spec.http`
对非 http 的 kind **恒为** `None`。于是这条规则**永远不触发**，误配被静默忽略。

**为什么这条最危险**：它不是"没生效"，而是**看起来生效了**。比不写更糟——
review 时你以为有防护。

**修法**：改在**原始数据**（`raw["http"]`）上判。

**连带教训**：写加载期校验时，**每加一条都要问"它在什么输入下会触发"**，
并**为它写一条会失败的用例**。没有失败用例的校验等于没有。

---



### 2.9 规范化时手工重建数据类 → 静默丢字段

**现象**：`registry.register` 在 id 需要 `strip()` 时手工重建 `CapabilitySpec`，
**漏掉了** `tenant_scoped`（既有潜伏 bug）。本次一口气加了 6 个字段后，
爆炸半径成倍放大。

**修法**：`dataclasses.replace(spec, capability_id=cid)`——**永不手工重建**。

**可复用判据**：**数据类每加一个字段，就去 grep** `ClassName(` **的手工构造点。**
它们是"加字段"这个动作唯一的长期成本。

---



### 2.10 reload 按"本次声明的 id"注销

**现象**（多文件后必现）：清单里**删掉**的能力 reload 后仍留在注册表；
更糟的是 reload A 文件会把 B 文件的能力一起注销掉——**静默失效，不报错**，
表现为"某个能力莫名其妙消失了"。

**修法**：按**文件**记 id 集合（`_FILE_IDS[path]`），reload 只注销**本文件此前注册的** id。

---



### 2.11 幂等占位行无租约 → 卡死

**现象**（设计缺陷，尚未实现，提前记录）："先插 `in_flight` 占位行抢执行权"的做法，
如果第一次插入后进程崩了，这个 key **永远** `in_flight` → 后续同 key 全被拒，**而且是静默的**。

**修法**：

- **租约（lease）+ TTL**：`in_flight` 超过 N 分钟视为失效，允许重试，但在凭据上标"第 N 次尝试"
- **把发起时的参数快照一起写下**，让人工在租约失效时能判断"该重试还是该去下游查"

**可复用判据**：**任何"占位/锁/状态机"都要有超时和释放路径**，并明确"卡死后谁来处理"。

---



### 2.12 就绪探针用 `curl` 不可靠

**现象**：等待服务就绪的循环被"骗过"——服务其实没起来。

**根因**：有出口代理时，**连一个没人监听的端口 curl 也会拿到 502**，
而 `curl` **退出码仍是 0**（没加 `-f`）。

**修法**：用 `curl -f`，或直接判真实监听：

```bash
lsof -nP -iTCP:18080 -sTCP:LISTEN
```

**CI 里同样适用**——这是生产/CI 环境的问题，不只是本机。

---



### 2.13 多实例下进程内注册表分叉

**现象**：能力清单是进程内 dict，多实例各自一份；配置变更时窗口期内不一致。

**现状**：**没有假装解决**。当前策略是让它**可见**：

- 每个实例上报自己加载的清单版本号（已写进 span metadata）
- 版本不一致 → 告警（不阻断）
- **行为契约用语言无关的 fixture 守住**：注册表可以短暂分叉，但
「同一个 id + 同一组参数 → 同一套错误码」不能分叉

## 3. ★★ 生产可能（取决于环境或升级）



### 3.1 `tags_any`（收窄）与 `allow_tags_any`（放宽）方向相反

`CapabilityFilter.tags_any` 是**收窄**（交集），所以把"域白名单"写成
`kinds={"local_fn"}, tags_any={"oa"}` 会得到**空目录**——存量 `local_fn` 没有 `oa` 标签。
**不报错，静默失效。**

按域放开新 kind 要用新增的 `allow_tags_any`（**只豁免** `kinds`，
不放宽 `deny_high_risk` / `deny_write`——否则一个 tag 就等于换到全部豁免）。

**可复用判据**：**同一名词的两种语义要写在同一处 docstring 的同一张表里**，
并在类型注释、字段表、用例**三处**标注方向。这类坑靠记忆防不住。

### 3.2 Spring Boot 4 用 Jackson 3

- 包名 `tools.jackson.*`（**不是** `com.fasterxml.jackson.`*）
- `JacksonException` 是**非受检异常**（`catch (IOException)` 会报"异常从未抛出"）



### 3.3 Boot 4 拆分了测试自动配置模块

`@AutoConfigureMockMvc` 已移出 `spring-boot-test-autoconfigure`，直接引**编译不过**。
替代：`@SpringBootTest(webEnvironment=RANDOM_PORT)` + `@LocalServerPort` + **JDK** `HttpClient`
——零额外依赖，且比 MockMvc 更接近"真的发出去了"。

### 3.4 `SERVER__PORT` 类环境变量覆盖配置文件

宿主注入 `SERVER__PORT`（双下划线）时，Spring 的宽松绑定会当成 `server.port`，
**覆盖** `application.yml`，服务跑到别的端口上（若被占则启动失败）。

**修法/规避**：命令行参数优先级最高 → `--server.port=18080`。

**可复用判据**：**12-factor 部署里，环境变量 > 配置文件。**
配置没生效时，先 `env | grep -i` 一遍，别先怀疑代码。

## 4. ★ 本机 / 沙箱特有（是环境问题，不是代码问题）

保留在此仅为**在别的环境复现时少走弯路**：


| 现象                      | 根因                                               | 规避                                       |
| ----------------------- | ------------------------------------------------ | ---------------------------------------- |
| 命令"莫名其妙没生效"             | `pkill -f '<jar名>'` 会匹配到**执行它的 shell 自身**        | 只按捕获的 PID 杀                              |
| 上一步起的服务下一步就没了           | 工具的后台进程跨调用被回收                                    | 在**同一条命令**内完成"起服务 → 等监听 → 跑测试 → 杀进程"     |
| 大批测试 **ERROR**（不是 FAIL） | 沙箱文件代理拦截 `tmp_path` 的 mkdir                      | pytest 加 `--basetemp=.pytest-tmp`        |
| 「不支持发行版本 25」            | `$(/usr/libexec/java_home -v 26)` **回落到 JDK 21** | 显式 `JAVA_HOME=/opt/homebrew/opt/openjdk` |


> 判别方法：把改动 `git stash` 后重跑。**在原始代码上同样失败 → 环境问题**。
> 本仓 `tests/test_chat_ws.py` 的 asyncio 偶发失败就属此类。

## 5. 提炼出的六条判据（跨项目可复用）

1. **一条设计主张，只有在对端真的收到请求之后，才算验过。**
  `FakeTransport` 证得了逻辑，证不了"发得出去"。
2. **断言"对端被调用了几次"，比断言"我们返回了什么"更接近真问题。**
  （写操作不重发 → 断言 `attempts == 1`）
3. **"检查"与"使用"是两件事。** 任何"我们校验了 X"的代码，都要问"X 真的被用上了吗"。
4. **没有失败用例的校验等于没有校验。** 每加一条加载期规则，配一条会触发它的用例。
5. **凡是拼进协议位置的字段（头 / URL / 文件名 / SQL），单独想一遍编码边界**，
  测试参数里必须有一个非 ASCII 样本。
6. **行为断言 > 结构断言。** 去翻 `opener.handlers` 找 `ProxyHandler` 会问错对象；
  把代理指向不可达地址、看能否调通，才是真的在问。
