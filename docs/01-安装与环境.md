## 2. 关键坑：pnpm 版本

- 项目 `packageManager` 钉死 **pnpm 11.7.0**。
- PATH 里 deepseek-harness checkout 的 pnpm shim 是 **11.28.5**，直接跑会报版本不符。
- **解法**：用 corepack 激活被钉住的版本——`corepack pnpm install && corepack pnpm build`。

## 3. 安装步骤（实际执行顺序）

```bash
# 1) 升级 DSH（engines 不满足时项目拒绝运行）
npm install -g @deepseek-ai/dsh@0.2.1-rc.3

# 2) 依赖 + 构建（注意用 corepack，见上）
cd $PROTO && corepack pnpm install && corepack pnpm build

# 3) 创建 superagent profile（从 web 模板复制，保证插件/端口配置成套）
dsh superagent --from-default-profile web

# 4) 以 link 方式安装本仓库插件（改代码即生效）
dsh plugin --profile superagent add "link:$PROTO"

# 5) 创建 bot 专用 gh 身份（详见 02 篇）
# 6) 写 profile 补丁（详见 03 篇）后启动
scripts/dsh-superagent start
```

## 4. profile 补丁 `~/.dsh/profiles/superagent/cordis.patch.yml`

```yaml
- id: webserver
  config:
    host: 127.0.0.1
    port: 3082          # 与默认 web profile 的 3080 错开
- id: dsh-superagent
  config:
    stateDir: /Users/cyning/.dsh/state/superagent
# （后续 04 篇在此追加了 llm provider 配置）
```

**决策理由**：superagent 与日常用的 web profile（3080）是两个完全独立的 profile——互不干扰，各抱各的状态库；superagent 挂了对日常编码零影响。端口错开是硬要求。

## 5. 面板访问

- 地址：`http://127.0.0.1:3082/?token=<token>`
- token **每次重启都会变**，从最新日志取：

```bash
grep -o 'http://127.0.0.1:3082/?token=[^ ]*' \
  $PROTO/.artifacts/dsh-superagent-superagent-*.log | tail -1
```

> 📷 **[截图占位]** 面板首屏（Overview tab）：六 tab 全貌；token 需打码
> 拍摄位置：面板 → Overview

## 6. 服务管理

```bash
cd $PROTO
scripts/dsh-superagent status    # 退出码 0 + 全部件 ready 才算健康
scripts/dsh-superagent restart   # 改 cordis.patch.yml / prompts / 升级 DSH 后必须
scripts/dsh-superagent stop
```

> 📷 **[截图占位]** `scripts/dsh-superagent status` 输出：全部件 ready（作为健康基线样例）

**注意**：升级 DSH 后不 restart，面板会报 `Failed to load plugins`——superagent 进程还跑着旧插件二进制。
