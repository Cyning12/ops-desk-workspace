# 03 · 核心配置四件套

> 服务起来之后，通过 Management API 依次落地四份配置：source / policy / executor / prompts。
> API 用法：`http://127.0.0.1:3082/orchestrator/api`，**必须带 header `x-orchestrator-request: 1`**。
> 面板 UI 与 API 写的是同一份数据；批量/脚本化改建议走 API，可视化确认用面板。

## 1. Source（GitHub 接入）

```json
{
  "kind": "github",
  "repository": "Cyning12/ops-desk-api",
  "cli": "/Users/cyning/.local/bin/gh-agent",
  "revision": 1
}
```

决策理由：

- **一个部署只绑定一个仓库**（产品约束，不是配置选择）。
- `cli` 指向 02 篇的 wrapper——bot 的一切 gh 操作都用它的独立身份和代理。
- `revision` 从 0→1 会**触发重启**才完全生效。

## 2. Policy（授权白名单）

```json
{
  "sources": {
    "github": {
      "allowed": [{ "id": "Cyning12" }],
      "bots": []
    }
  }
}
```

- 保留默认的 copy/visual 规则（文本搬运类工作直接放行的小额度授权）。
- `allowed` 只放 **Cyning12 一个人**——起步从窄，之后按需加。
- `bots` 为空 = 不允许 bot 账号直接驱动（防 bot 互相触发循环）。

**为什么"名单内未 @" 会静默忽略**：这是 002-authorization.md 的 admission 规则——只有 @ 了 bot 的评论才构成 mandate。工单不触发时先查是不是忘了 @（见 09 篇症状 10）。

## 3. Executor（执行资源）

```json
{
  "prepare": "<从 ~/src/ops-desk-api 克隆 fetch + worktree add 的模板>",
  "maxWorkers": 3,
  "model": null
}
```

- prepare 模板：每个 worker 从绑定克隆 `~/src/ops-desk-api` 新建 worktree，互不污染。
- `maxWorkers: 3`：个人部署够用，也能防止失控并行。
- `model: null` = 跟随 profile 默认模型（见 04 篇）；要对某类任务单独换模型时在这里指定。

> 📷 **[截图占位]** 面板 Execution tab：worker 槽位（running/queued/maxWorkers）与 prepare 模板
> 拍摄位置：面板 → Execution（有任务在跑时拍，能看到 working ticket）

## 4. Prompts（提示词）

初始改写（revision 1）两件：

1. **delivery 段删除 auto-merge 相关内容**，改为 "A person merges every PR … Never enable auto-merge"——merge 权永远在人。
2. 增加提交署名规则："Every commit names cyning12-bot as its author, with the email in `$DSH_SUPERAGENT_GITHUB_COMMIT_EMAIL`"。

之后追加了 spec-wave 六纪律（revision 2）和 00 帽委托规则（revision 3），全文见 [05 篇](05-审批流与授权机制.md)。

改写要点：面板 Prompts 页可视化改，或 `PUT /orchestrator/api/prompts`（带 `baseRevision` 做乐观锁）；升级后若有段落标 "Default updated"，先 review 再决定保留哪版。

> 📷 **[截图占位]** 面板 Prompts 页：scope 段六纪律 + revision 3 的委托规则可见；如有 "Default updated" 标注也一并拍到
> 拍摄位置：面板 → Prompts

## 6. 配置生效速查

| 改了什么 | 要不要 restart |
|---|---|
| source / policy / executor / prompts（API 或面板保存） | 否（next-request 生效） |
| `cordis.patch.yml`（端口、模型 provider、stateDir） | **是** |
| 升级 DSH | **是**（否则 Failed to load plugins） |
| gh-agent wrapper 内容 | 否（每轮 poll 新起 gh 子进程） |
