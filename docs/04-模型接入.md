# 04 · 模型接入

> 曾问："superagent 不支持三方模型 API Key 吗？"——支持，而且 key 早就存好了，缺的只是 provider 配置。

## 1. 机制：模型接入在 DSH 层，不在 superagent

- 插件：`dsh-llm-pi-ai`（源码 `deepseek-harness/packages/llm/llm-pi-ai/`）。
- 支持**任意 OpenAI 兼容的 baseURL + apiKeyEnv**——三方 key 天然可行。
- key 从 `~/.dsh/.credentials.yaml` 的 refs 段按 env 名注入（见 02 篇），不进 shell、不进 prompt。

## 2. 一个 setup 遗漏

superagent profile 从 web 模板创建时**漏配了 llm provider**（web 模板自带，superagent 路径没有）。症状：一切正常但模型调用失败/缺失。查法：对比 `~/.dsh/profiles/web/cordis.patch.yml` 与 superagent 的。

## 3. 修复：在 `cordis.patch.yml` 追加

```yaml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      kimi-coding:
        models: []                      # 空 = 用目录默认模型清单
        apiKeyEnv: KIMI_CODING_API_KEY  # 值在 ~/.dsh/.credentials.yaml
- id: agent-default-model
  config:
    provider: kimi-coding
    model: kimi-for-coding
```

然后 `scripts/dsh-superagent restart`，`status` 退出 0 + 全部件 ready。

## 4. 选层规则

| 想改什么 | 改哪里 |
|---|---|
| 全 profile 换默认模型 | 上面 `agent-default-model.model`，restart |
| 只给执行 worker 换模型 | Executor 设置的 `model` 字段 |
| 只给评估（Eval）换模型 | Eval 设置的 `model` 字段 |
| 加一个新 provider | `llm-pi-ai.providers.<name>` + 对应 `*_API_KEY` 进 credentials refs |

留 `null` = 跟随 profile 默认，当前即 `kimi-for-coding`。

## 5. 已知噪音

日志可能出现 `stored version 2 != expected 1` 的 schedule 存储版本警告——只影响 superagent profile 自身的 schedule 存储，不影响功能，3080 profile 的健康检查不受影响。可忽略。
