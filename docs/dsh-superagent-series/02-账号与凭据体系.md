# 02 · 账号与凭据体系

**TL;DR：** 双账号——Cyning12 做人（决策/merge），cyning12-bot 做执行；gh 身份用 GH_CONFIG_DIR 隔离；密钥统一存 `~/.dsh/.credentials.yaml` refs 段按 env 名注入；任何文档只写变量名不写值。

> 双账号设计：主账号 = 人（决策/merge/验收），bot 账号 = 执行体（读写代码、回评论）。
> 一切凭据分流的原则：**能隔离就隔离，能环境变量就不写死，能专用身份就不用主身份**。

## 1. cyning12-bot 账号史（一个真实的坑）

- 账号 2017 年注册，但**长期未激活**——GitHub 对未激活账号返回 404，一开始以为用户名被占/不存在。
- 用户手动激活后，显示名一度叫 "CyningMM"，后来改名为 **cyning12-bot**。
- 以 Cyning12 身份向私有仓库 `Cyning12/ops-desk-api` 发出 collaborator 邀请（**write** 权限）。
- bot 侧用 **token 方式**完成 `gh auth login`（不能走浏览器 OAuth 流程），push 权限验证 OK。

**教训**：给 bot 用老账号时，先确认它处于激活状态（网页能打开 profile 才算）。

## 2. gh-agent wrapper：给 bot 一套独立 gh 身份

`~/.local/bin/gh-agent`：

```bash
#!/bin/bash
export GH_CONFIG_DIR="${GH_CONFIG_DIR:-$HOME/.config/gh-agent}"
# 代理默认值：仅当外部没设时才生效（见 06 篇网络故障）
: "${https_proxy:=http://127.0.0.1:7890}"
: "${http_proxy:=http://127.0.0.1:7890}"
: "${all_proxy:=socks5://127.0.0.1:7890}"
export https_proxy http_proxy all_proxy
export no_proxy="127.0.0.1,localhost"
export NODE_USE_ENV_PROXY=1
exec gh "$@"
```

**决策理由**：

- `GH_CONFIG_DIR` 隔离——bot 的 token、hosts 存在 `~/.config/gh-agent/`，与主账号 `~/.config/gh` 完全分开，互不串号。
- superagent 的 Source 配置里 `cli` 字段填这个 wrapper 路径，Executor prepare 模板里也用 `gh-agent` 拉取代码。
- 代理默认值用 `: "${var:=default}"` 形式——外部已设则不覆盖；这是后来修网络故障时补的（详见 06 篇）。

## 3. 密钥存放：`~/.dsh/.credentials.yaml` 的 refs 段

```yaml
refs:
  DEEPSEEK_API_KEY: <redacted>
  ZAI_CODING_CN_API_KEY: <redacted>
  KIMI_CODING_API_KEY: <redacted>
```

- **DSH 全局**，所有 profile 共享；dsh 进程自己把这些注入子进程环境，**不走 shell**——所以 tmux session 里 `env` 看不到它们是正常的。
- 模型插件用 `apiKeyEnv: KIMI_CODING_API_KEY` 这类名字引用，密钥本体永不进 prompt、不进面板、不进文档。

**纪律**：任何文档（包括本系列）只写 env 变量名，不写值。

## 4. 双账号分工表

| 动作 | 身份 | 说明 |
|---|---|---|
| 开 issue / 评论签认 / 授权 | Cyning12（人） | 授权的载体必须是 issue 线程（绑定工单、可审计） |
| 读通知 / checkout / push 分支 / 开 PR / 回评论 | cyning12-bot | 专用执行账号，最小权限（单仓库 write） |
| 审 PR / Approve / merge | Cyning12 或受委托人 | 见 05 篇三层审批 |
| 发签闸/授权指令评论 | Cyning12 或受委托人 | 00 帽代录时引用这条评论作为签认依据 |

## 5. 换账号/换机器时

1. 新账号激活 → 邀请 collaborator（write）→ token 登录：`GH_CONFIG_DIR=~/.config/gh-agent gh-agent auth login --with-token`。
2. 验证：`gh-agent auth status` + 对目标仓库试 push 一个分支。
3. superagent Source 配置里的 `cli` 指向新 wrapper（或原路径不变）。
