核心原则回顾（来自 000-philosophy.md）：

1. **一个部署绑定一个仓库**——它看到的全部世界就是那个 repo。
2. **白名单起步**——Policy 只放 Cyning12；要对它说的话负责（它分不清玩笑）。
3. **人工闸是特性不是麻烦**——spec-wave 的 HG-* 闸强制"人停下来签一次"，这是防幻觉的第一道墙；委托授权（00 帽）只是让"签"这个动作可以代执行，决策依据必须留痕。

2. **合并三件套**：`gh pr merge` 返回 rc=0 不算数，必须验证 merged:true + review 落了 + master HEAD 前进；
3. **受理必须 @**：issue 正文/评论里没有 `@cyning12-bot` 就不触发（名单内未@ → 纯代码 ignore，零 token）；

5. **issue 发起 fix task 的标准动作**：@bot + 10 帽边界 + 机制/证据/要求 + 受理依据引用；
6. **跨仓转派清单引注必须落盘前核实**（web#93 判例：凭记忆转写的锚点全仓不存在，bot 开工即撞墙——引用行号/符号前先 grep 实证）。
