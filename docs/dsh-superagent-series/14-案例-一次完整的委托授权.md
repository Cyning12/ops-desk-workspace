## 停线点复盘（机制的健康性证据）

1. **选项裁决**（受理前）：bot 对 A/B/C 不代选，等维护者签认——授权范围内的事自己做，
   范围外的决策留人。
2. **预支签认**（后续 #323 链 PR #326 中发现并修正为判例④）：留痕必须引用已发生的证据。

## 可复用的委托模板

```
@cyning12-bot <受理范围与帽级授权>；
00 帽全程自签过程文档（闸表签收 + 审查文），签认依据 = 本评论；
出货后由 lead 审查验收并决策 merge；
红线：<按 task 性质给 2-4 条机检可断的红线>；
如有红线冲突 / 内容阻塞 / 与签认不符，停下报，不静默消化。
```

## 判例要点

- **委托成立的三个前提**：规则已写进 prompts（双态规则）；每棒 invoke 留痕可审计；
  定时巡查兜底捕获出货（不靠人盯）。
- **防越权的两条保险**：授权评论明示帽级与红线；无授权时 bot 的双态规则强制"停并问"。
- **正确性 > 字面**：bot 对"按单据自身 run_id"的忠实解读（末位反查）优于机械执行字面——
  因为它把理由写进了文档，维护者可在审查时否决。
