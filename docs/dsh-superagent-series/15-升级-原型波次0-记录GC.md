## 波次 0 设计裁定（关键取舍）

1. **范围三件套**：① settled 收据按龄删除（默认 30 天）；② settings/prompts 版本快照各留最近 N 版（默认 50）；③ Runtime 日度 GC pass（启动即跑 + 每 24h，lifetime 守卫）。
2. **推迟项**：trigger/decision/thread/ended-ticket 的 GC 推到波次 1——thread.meta 存 source 读取位标，删 thread 会丢位标导致旧消息重复摄入，需先设计位标保留。宁可窄而正确，不要广而冒险。
3. **幂等论证是硬门槛**：store.ts 原注释「Receipts are retained permanently so message IDs are idempotent」。收据可删的论证：消息 ID 由内容派生 + 保留窗（天）≫ 重试窗（5s 倍增至 300s × 3 次失败）+ 重排队只在 Engine 重放同 reply 时发生。论证写进 gc.ts 类 doc。
4. **配置模式照抄先例**：receiptRetentionDays/versionRetention 走 Machine volatile 键（同 promptMaxChars 模式），limits.ts 加边界，面板 deployment 页可见可改。

## 实现要点（3df91eb，16 文件 +254/-15）

- **settledAt 戳**：receipts.settle 两分支统一盖戳；无戳旧档 json_extract 比较为 NULL → 永久保留（零迁移）。
- **gcSettled**：DELETE outbox WHERE status!='pending' AND settledAt < cutoff，一条 SQL。
- **Versions.prune(limit, keep)**：按 revision 倒序留前 N + current + keep()（keep 钉住会话仍在读的 prompt 版本）。
- **GarbageCollector.run()**：三项收集包在一个 store.atomic 里；任何异常 → warn + 返回 undefined，**绝不抛进 Runtime**。
- **面板面**：http.ts machineView + deployment.tsx + locales.ts 中英两键同步，测试夹具两处补 30/50。
