## 设计裁定：隔离 = 解析顺序 + 钉版位置，不是新进程模型

开放问题原文：agent profile 要用自己的 pinned DSH 安装，避免别处升级 DSH 弄坏它。
勘察发现现状两处弱点：006 安装块教的是 `npm install -g`（全局）；`scripts/dsh-superagent` 的 start
用 `shutil.which('dsh')` 裸解析 PATH——全局一升级，服务下次 restart 就换了引擎。

裁定三件套：
1. **钉版位置**：`.dsh-runtime/`（独立 prefix，`npm install --prefix .dsh-runtime @deepseek-ai/dsh@0.2.1-rc.3`），
   不进 repo 依赖、不进 git（.gitignore 登记）；profile 创建与 plugin add 两个一次性命令也改用该二进制。
2. **解析顺序**：`DSH_SUPERAGENT_DSH` 环境覆盖 → `.dsh-runtime/node_modules/.bin/dsh` → PATH 回退
   （回退可用但启动时打印 unpinned 提醒）。
3. **可执行校验**：`dsh --version` 跑不通（不存在/退出非零）即拒启动并指回钉版安装命令。

## 实现要点（ebdd14e，4 文件）

- `scripts/dsh-superagent`：新增 `resolve_dsh()`（docstring 写明优先级与意图），start 改调它；
  解析结果与「pinned local install / unpinned PATH binary」标记打印到启动输出。
- `.gitignore`：+`.dsh-runtime/`。
- `docs/006-deployment.md`：What runs 点明钉版语义；安装块改为 clone→build→本地钉版→两个 dsh 命令全走
  `.dsh-runtime`；Upgrade 第 3 步补「要动 DSH 本体先重钉 `.dsh-runtime`」。
- `docs/007-architecture.md`：第二个开放问题划除并指 006（006<007 链接合法）。

## 验收

  （FileNotFoundError 泄漏已补 try/except OSError）；伪造 `.dsh-runtime` shim 验证本地钉版优先。

## 教训

- **隔离的敌人是默认值**：不改全局装机行为，只改自己脚本的解析顺序——侵入面最小、语义最直白。
- 写脚本测试不存在的文件（scripts/dsh-superagent 无 .py 后缀）要用 SourceFileLoader 加载，spec_from_file_location 会返回 None。
