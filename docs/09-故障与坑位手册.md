# 09 · 故障与坑位手册

> 按症状索引。每条：症状 → 根因 → 修法。都是真实踩过的。

## 触发类

**S1. 开了 issue / 评论了，bot 毫无反应**
设计使然：Policy 名单内也必须 **@cyning12-bot** 才构成 mandate。普通评论和开 issue 不触发。

**S2. @ 了也没反应，bot 的通知 API 恒空**
根因：bot 账号 settings/notifications 里 "Participating and @mentions" 的 **"On GitHub"** 未勾选（老账号默认可能从没开过），API 因此恒空。修法：网页登录 bot 账号开开关。

**S3. 通知开关开了，之前的 @ 还是不触发**
根因：**轮询游标**——`~/.dsh/state/superagent/orchestrator.sqlite` 表 `kv` 里 `github-cursor:<issue>` 记录上次读取时间，只取游标后的事件，旧事件不补发。修法：补发一条相同 @ 评论制造新事件（或操作游标，不推荐）。

## 网络类

**S4. 面板报 GitHub 来源连续轮询失败 / EOF**
根因：tmux server 环境无代理变量（新 session 继承 server 环境而非你的终端）。修法：双层——`tmux set-environment -g` 注入代理 + gh-agent wrapper 硬编码代理默认值（`: "${https_proxy:=...}"` 仅缺省时设）。不需要 restart dsh。

**S5. `gh pr review` 报 GraphQL EOF**
瞬时网络问题。直接重试即可（建议循环 3 次带 sleep）。

## gh CLI 类

**S6. `gh pr merge` 返回码 0 但 PR 没合并**
静默失败真实发生过。**永远以验证为准**：合并后必须查 `gh api repos/.../pulls/N --jq .merged` = true 且 master HEAD 前进。不对就重试。

**S7. `gh api ... -f body=@/tmp/x.md` 发出字面 "@/tmp/x.md"**
`gh api` 的 `-f` 不做文件展开。修法：`gh issue comment N --body "$(cat /tmp/x.md)"`。

**S8. `gh api repos/.../pulls/N/files` 取不到 `.path`**
该 API 的字段名是 **`.filename`**，不是 `.path`（`gh pr view --json files` 才是 `.path`）。

**S9. `gh issue comment` 没有 `--json` flag**
想拿返回的 comment id 时用 `gh api repos/.../issues/N/comments -f body=...`。

## 配置类

**S10. superagent 模型调用失败 / 没有 provider**
根因：从 web 模板复制 profile 时漏配 llm provider（已知 setup 遗漏）。修法见 04 篇。

**S11. 日志 `stored version 2 != expected 1`（schedule）**
存储版本警告，仅影响该 profile 自身 schedule，功能不受影响，可忽略。

**S12. 升级 DSH 后面板报 `Failed to load plugins`**
没 restart。`scripts/dsh-superagent restart`。

**S13. pnpm 报版本不符（项目要求 11.7.0，PATH 里是 11.28.5）**
项目 `packageManager` 钉版与全局 shim 冲突。修法：`corepack pnpm`。

## 流程类

**S14. bot 交付质量差 / 跑偏**
按顺序查：① issue 里的授权/签认是否写清了裁决口径 ② 红线是否可机检 ③ prompts scope 段纪律是否生效（revision 号）。多数问题是授权本身模糊，不是模型不行。

**S15. 想撤掉某个闸的委托**
直接在 issue 线程发评论撤回（"撤回 xx 授权"）+ 如需全局收紧，编辑 prompts scope 段（面板 Prompts 页或 PUT API，带 baseRevision）。
