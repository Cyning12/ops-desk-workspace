# 07 · 脱敏匹配方案思路记录（外部沟通纪要整理）v1

> 来源：与外部沟通了解到的应用方案，本文档为思路记录与拆解，**非本仓已实现设计**。
> 状态：思路稿 v1（2026-10-26）· 待评审；如落地需走 SPEC 流程。
> 一句话：把「人」的敏感信息挡在 LLM 之外——LLM 只看脱敏特征+匿名标识做匹配，服务商凭标识在服务端反查执行动作。

---

## 1. 方案三段式（原始思路）

| 段 | 动作 | 关键约束 |
|---|---|---|
| ① 脱敏入池 | 用户敏感信息脱敏，附加特征属性+可反查唯一标识 | 标识**非真实数据库 ID**（不可推导、服务端可反查） |
| ② LLM 匹配 | LLM 对脱敏候选集分类/匹配，筛出目标唯一标识 | LLM **只输出标识**，永远接触不到明文 |
| ③ 服务端反查执行 | 服务商用唯一标识反查真实身份，执行对应动作 | 反查与执行都在服务端可信域，带审计 |

核心信任边界：**LLM 是不可信执行环境**——它能看到的任何东西都可能被 prompt 注入、日志、训练数据管道泄出，所以明文 PII 永远不进 prompt。

## 2. 第②段详细拆解：LLM 匹配方式谱系

按「LLM 承担的智能比重」从轻到重排列，实际方案通常是组合拳：

### 2.1 规则预筛 + LLM 精判（推荐基线）
- 确定性代码先按结构化属性（城市/年龄段/标签）把候选集从 N 砍到 K（K 控制在 prompt 可承载的几十~几百）
- LLM 只对 K 个候选做语义精判
- 优点：成本可控、可解释、LLM 幻觉爆炸半径被候选集物理限制
- 对应 ops-desk 哲学：与 strategy_builder 收窄菜单同构——**收窄管输入空间**

### 2.2 向量召回 + LLM 重排（特征可嵌入时）
- 脱敏特征文本化 → embedding → ANN 召回 top-K → LLM rerank
- ⚠️ 嵌入本身可能泄漏信息（嵌入反演攻击）：embedding 必须在自有可信域计算，不给第三方模型 API 发明文特征

### 2.3 LLM 直接分类（候选集小时）
- zero-shot/few-shot 把候选脱敏档案全量进 prompt，让模型直接输出命中标识
- 适用：K 小（<50）、特征描述短；K 大时成本与注意力稀释都不可接受

### 2.4 结构化输出匹配（工程收口）
- 强制 LLM 走 function calling/JSON schema 输出：`{matched_ids: [...], confidence, reason}`
- 关键纪律（与 capability 可见集同理）：**服务端必须校验返回的 id ∈ 当次候选集**——模型幻觉出一个不在集合里的 id 时，fail-closed 判无匹配，绝不拿幻觉 id 去反查（否则等于给幻觉开了任意用户执行通道）

### 2.5 分层/分桶匹配（候选集巨大时）
- 粗桶（规则/向量）→ 细匹配（LLM）→ 单点确认（LLM 二次确认 top-1）
- 每层都有「无匹配」显式出口，禁止层层兜底硬猜

### 2.6 多路融合（准确率要求高时）
- BM25（特征文本）+ 向量 + 规则三路召回合并候选，LLM 只做最终裁决

## 3. 第①段拆解：脱敏与标识设计

### 3.1 脱敏粒度
| 手法 | 说明 | 风险 |
|---|---|---|
| 直接标识符剔除 | 姓名/手机/身份证/邮箱不入池 | 基础项 |
| 泛化 | 年龄→年龄段、精确地址→城市 | 泛化不足可被重识别 |
| 假名化 | 真实值替换为稳定假名 | 假名映射表成为新靶子 |
| k-匿名校验 | 任一特征组合命中人数 ≥k 才入池 | 小语种/罕见组合是漏网口 |

⚠️ **链接攻击**是最大隐患：多个脱敏特征组合起来可唯一锁定真人（邮编+生日+性别可重识别 87% 美国人的经典结论）。特征属性不是给得越多匹配越准越好——每加一个维度都在缩小匿名集。

### 3.2 唯一标识（匿名 ID）设计
- **不可推导**：HMAC(secret, user_id) 或随机 UUID 映射表，防枚举防猜测
- **作用域限定**：按场景/按批次签发不同标识，跨场景不可关联（防跨批次拼图）
- **时效性**：标识带 TTL，过期不可反查——与 ops-desk 委派令牌同构（600s TTL 禁续期）
- **反查单行道**：只有服务端可信域持映射，LLM 侧拿到的标识在数学上不可反解

## 4. 第③段拆解：反查与执行

1. LLM 返回 `{matched_ids, confidence, reason}`
2. 服务端校验：id ∈ 当次候选集（防幻觉）、标识未过期、本次会话有权对这些 id 发起动作
3. 映射表反查真实身份 → 执行动作（发通知/建单/推荐等）
4. 全程审计：谁发起、LLM 选了谁、理由是什么、执行了什么——**选择理由落盘**是这类系统的特殊要求（匹配不可解释=合规死穴）

## 5. 失败模式清单（how-fail 预演）

| 失败模式 | 后果 | 对策 |
|---|---|---|
| LLM 幻觉 id | 对随机用户执行动作 | 候选集白名单校验，集外 id 显式失败 |
| 候选集过大直接进 prompt | 成本爆炸+注意力稀释漏匹配 | 2.1/2.5 分层收窄 |
| 特征过细可重识别 | 脱敏失效，合规事故 | k-匿名校验+特征最小化 |
| 标识被枚举/猜测 | 任意用户反查 | HMAC/随机映射+TTL+速率限制 |
| 注入攻击篡改匹配指令 | 匹配结果定向操纵 | LLM 输出仅作候选，执行层独立鉴权 |
| 「无匹配」被兜底成硬猜 | 静默错误匹配 | 无匹配是一等结果，显式上报 |

## 6. 与 ops-desk 哲学的映射（面试可串联）

| 本方案 | ops-desk 对应 | 共同原则 |
|---|---|---|
| 规则预筛收窄候选集 | strategy_builder 收窄能力菜单 | 收窄管输入空间 |
| 返回 id 候选集校验 | baseline_filter 防幻觉 id（反向同构） | 模型输出永远要过确定性校验 |
| 匿名标识 TTL+不可推导 | 委派令牌 600s TTL 禁续期 | 凭证最小权限+最短时效 |
| 无匹配显式出口 | fail-closed 错误显式化 | 绝不静默兜底 |
| 匹配理由落盘审计 | 闸链 span/回执审计 | 决策必须可取证 |
